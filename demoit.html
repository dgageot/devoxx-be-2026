03Prove

An agent improves the prompt

Inspect failures → edit a candidate → rerun the same evals

Optional live detour; skip straight to the final-exam boundary if short on time. This dedicated optimizer is a development agent, not a coordinator for building teams. It edits a disposable copy of 11-builder.yaml and invokes the native eval CLI; there is no built-in optimizer tool.

Run from the repository root with the same Docker Desktop, prepared PokéAPI, healthy arena and provider access as the previous evals. The shell asks for approval in strict mode: inspect each command before allowing it. Each full eval uses a 600-second shell timeout. Do not use --yolo or an always-allow shell grant.

The agent creates a unique .state/prompt-loop/run.* workspace and copies the builder, team-building.md and eval-setup.sh together. Native eval mounts the candidate's parent at /configs, so omitting the support files would break setup. The source builder and captured baselines remain untouched.

First measure a fresh baseline: the same five development cases, five repeats, judge and unchanged model/tools. Then form one hypothesis per attempt and change only agents.root.instruction. Save each attempt's YAML and native results separately; compare with the best accepted Sessions JSON via --baseline. That native file contains summary metrics and per-session eval results. A nonzero exit can indicate regression or infrastructure failure: inspect the report rather than retrying until green.

Keep an edit only if it passes more repetitions and the native gate reports no regression; inspect per-case failures, cost and latency too. Stop at three candidate runs or 25/25. If nothing improves, keep the baseline. These are live results, not a captured claim of prompt-only gains or guaranteed reliability.

Filesystem tools read only the source/support files, development cases and workspace, and write only within the workspace. Those limits do not sandbox shell access: held-out exclusion, prompt-only edits and immutable raw results also depend on instructions and human command review. Do not read credentials or frozen old/ examples.

The optimizer's budget caps its own metered model calls, not the child eval processes or their judge calls; up to four repeat-5 suites incur separate spend. External commands may outlive a timeout or interruption. Stop only processes owned by this run and retain incomplete evidence for review.

Do not weaken tests, evidence checks or rules: TEAM-1, SPECIES-1, BUDGET-1, COVERAGE-1, DATA-1 and FAIR-1 remain unchanged. Failed/conflicting evidence requires human review (DATA-1); teams stay sealed (FAIR-1). No entry, tournament or state reset is authorized. A human reviews and freezes the chosen config before running held-out cases separately; the optimizer never reads those cases.

04Serve

See the agent's trace

Optional live detour; skip straight to MCP if short on time. Prepare the digest-pinned local Jaeger image before the talk: docker compose -p devoxx-tracing -f compose.tracing.yaml pull. No builds or pulls happen on stage.

Start terminals top to bottom: Jaeger, traced server, then client. Wait for Jaeger's viewer and the server's listening message before sending the request. The separate chat port 8082 avoids colliding with the previous application's server on 8080.

The endpoint enables OTLP/HTTP export to Jaeger on loopback 4318; --otel opts into tracing. Message content capture is explicitly false for this listener. Jaeger's viewer is on 16686. Both are local, not public services.

After the client completes, allow at least five seconds for batched spans to arrive. Choose the docker-agent service and click Find Traces; if the service is absent, refresh the embedded browser. Open the newest trace. Expand model and tool spans; compare durations, token usage when reported, lookup counts and errors. The search page does not auto-refresh results.

Trace hierarchy and timings are live observations, not a pre-captured score or a guarantee. An instrumented application can propagate trace context into the chat server; our Python client does not. PokéAPI and the arena need their own instrumentation to expose service-internal work.

The viewer helper stays attached to the first terminal. Ctrl-C or leaving the slide closes it and removes only the container created by that invocation. Docker detachment alone would not stop Jaeger, so the helper explicitly cleans up on terminal hangup. Occupied ports fail without stopping their owners. Jaeger stores traces in memory: leaving the slide discards them. A hard process kill or Docker outage can prevent cleanup and needs human review.

Jaeger accepts traces only. This Docker Agent build also exports metrics/logs to the same base endpoint; those exports can report unsupported-endpoint errors without invalidating trace export. Do not assume OTEL_METRICS_EXPORTER=none disables this build's explicitly constructed exporters.

Prompt/response content and tool arguments/results are omitted by default and capture is explicitly disabled here. Span metadata and error descriptions still need appropriate access and retention controls. Failed/conflicting evidence requires human review (DATA-1); sealed teams remain governed by FAIR-1. No entry or local match is requested by this demo.

04Serve

Run the packaged agent

Compose in the foreground. The same application client.

Before the talk, build PokéAPI with docker compose --env-file /dev/null build pokeapi and prepare the agent/backend images with docker compose --env-file /dev/null pull pokemon-arena arena. The agent image must support transform_json, max_output_bytes and structured output. If using local Docker Agent changes, build ../docker-agent under the docker/docker-agent:latest tag used by compose.yaml.

Install the 1Password CLI (op) on the Mac and enable its desktop integration in 1Password Settings > Developer. Unlock 1Password and ensure your account can read the Team AI Agent vault's cagent-proxy item and OPENAI_API_KEY field. The slide uses op run to resolve that reference on the host; approve the 1Password prompt when asked. No raw key needs to be exported before launching DemoIt. The selected gpt-6-luna model also needs provider access, and model calls still require networking.

Stop only your earlier chat listener on 8080 (Ctrl-C in its terminal) before starting Compose. Port 8000 should be free or occupied by this project's prepared PokéAPI container, which Compose reuses. Use the same repository root and default Compose project as the automatic PokéAPI helper; do not start a second project competing for port 8000.

Both commands wait for Enter. Start the left terminal first: no -d, no --wait, no builds or pulls. op run resolves the key for its Compose subprocess, and Compose injects it into the agent container's environment. --env-file /dev/null avoids loading a credential file. No launcher, temporary secret file or custom image is needed; the read-only root filesystem is unchanged. The key is visible to Docker administrators through container inspection; op run's output masking is best-effort, not a security boundary. Do not print the resolved Compose configuration. Wait for healthy dependencies and the agent's listening message on 8080 before running the right terminal. The Python client calls the same OpenAI-compatible API as before, now served by the container.

The Compose arena is private at arena:8090; keep the separate host arena on 8090 running for the later leaderboard slides. This request only proposes a team: no entry, practice or tournament is requested. Inspect TEAM-1, SPECIES-1, BUDGET-1 and COVERAGE-1; failed/conflicting evidence requires human review (DATA-1), and sealed entries remain governed by FAIR-1.

After the client completes, Ctrl-C in the left terminal stops the attached services, including PokéAPI. Compose containers can survive a terminal disconnect, so do not rely on leaving the slide for cleanup. If needed, run docker compose --env-file /dev/null stop from the repository root. The next slide terminal restarts prepared PokéAPI automatically; the host arena and its entries are untouched. Do not use down -v or reset the arena.
